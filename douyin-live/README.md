## 怎么改数

1. 打开模型的「假设」表，只改蓝色单元格；黄色底是对结论影响最大的关键假设。改完后所有表自动重算。
2. 关键开关：`CAL_MODE`（基线校准方式：1 按 7% 份额，2 按上月 4 万倒推，3 按实测核销间夜）、`SUP_HIRE`（一B 是否新招督导）、`MECH_ON`（总部主导订单是否按 8% 分成）、`CH_FEE`（渠道运营费）、`PAYBACK_RULE` / `PAYBACK_RULE_VAR` / `TROUGH_RULE` / `PESS_LOSS_RULE`（回本规则的三道门）、`PRESALE_V`（每家新店开业预售券数）、`PRICING_SEL`、`WEEKDAY_ONLY`。
3. 如需同步更新文档里的表格和图：在仓库目录执行

```bash
bash douyin-live/model/build_all.sh
```

该脚本依次运行 `build_model.py`（主工作簿与六个变体）、`recalc.py`（用 LibreOffice 重算公式，路径可用环境变量 `RECALC` 指定）、`tables.py`（把模型数值导出为文档表格）、`charts.py`（画图）、`build_doc.py`（用模板生成 Markdown、导出 Word）并转出 PDF。文档正文在 `report/住小叮抖音直播组织方案_股东决策文档.template.md`，占位符 `{{...}}` 由 `tables.py` 的输出替换。

## 口径（重要）

- 份额 = 抖音核销间夜 ÷ 系统间夜。决策人提供的"订单占比约 7%"默认按间夜份额使用；若一个抖音订单平均对应多个间夜，改 `SHARE_VPO`。
- 上月 4 万元与 7% 份额在"4 万 = 4% 分成 + 3.5% 管理费"的口径下吻合（核销 GMV 约 48 万）；若财务确认 4 万为纯 4% 分成，把 `CAL_MODE` 改为 2（份额约 14.5%）。
- 回本月 = 相对现状延续的总部累计净收益转正且此后不再转负的最早月份；规则判定 = 基准回本月不超过通过线（含固定人头 3 个月、零固定成本 6 个月）且基准现金谷底不低于允许值且悲观情景 12 个月亏损不超过允许值。
