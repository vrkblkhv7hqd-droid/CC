# HogentX · 给马来西亚酒店客户的汇报

面向马来西亚酒店老板（经理在场）的汇报，共 18 页：主线 13 页，附页 5 页。可在页面里切换 **中文 / English / Bahasa Melayu**。目的只有两个：让客户看懂**现在能用什么**、**值不值得试**。

事实口径以 2026-11-22 的《马来西亚酒店客户会谈资料》和逐项确认的 15 个决定为准；旧投资人汇报、旧开场视频里的数字和说法都没有沿用。

## 文件

| 文件 | 用途 |
|---|---|
| `HogentX-Malaysia-Hotel-Briefing.html` | **交付文件，打开默认中文**。单个文件，图片、字体、样式、脚本全部内嵌，断网可用 |
| `HogentX-Malaysia-Hotel-Briefing-EN.html` | 同一份内容，打开默认 English |
| `HogentX-Malaysia-Hotel-Briefing-BM.html` | 同一份内容，打开默认 Bahasa Melayu |
| `HogentX-Malaysia-Hotel-Briefing.pdf`、`-EN.pdf`、`-BM.pdf` | 三种语言的 PDF 备用稿，每页 1920×1080；投屏出问题时用，也方便转发 |
| `src/` | 源文件（`deck.html` 中文内容、`deck.css` 样式、`deck.js` 交互） |
| `i18n/strings.json` | 英文、马来文译文，和中文一一对应 |
| `assets/` | 6 张已核准的截图、字标、内嵌字体 |
| `tools/` | 生成与检查脚本，见下文“修改与重新生成” |

三份 HTML 都能在页面里切换三种语言，区别只是**打开时先显示哪一种**。发给客户时按对方的语言选文件：有些手机上的文件预览不运行脚本，那时只能看到文件默认的那种语言。

## 怎么用

**现场投屏**：用 Chrome、Edge 或 Safari 打开 HTML，有鼠标的宽屏会自动进入 16:9 翻页。

| 操作 | 按键 |
|---|---|
| 下一页 / 上一页 | → ← 、PageDown / PageUp、空格；翻页笔可用；触屏左右滑 |
| 第一页 / 最后一页 | Home / End |
| 目录（跳到任意一页，包括附页） | M |
| 切换语言（中文 → English → Bahasa Melayu） | L，或控制条上的“中 / EN / BM” |
| 全屏 | F |
| 放大截图 | 点击截图；再点一下图片看原始大小；Esc 关闭（来源标注一直跟着） |
| 直达某页 | 网址末尾加 `#9`（第 9 页是三个方案）；加 `?lang=en` 或 `?lang=ms` 指定语言 |

鼠标动一下，右下方会出现控制条（翻页、目录、语言、全屏、存为 PDF、阅读模式），几秒后自动隐藏。

**现场可以点、可以填的地方**（内容不保存，刷新即清空，换一位客户不会串；切换语言不会清掉已填内容）：

- 第 2 页：三个问题各有“有数据 / 凭经验 / 说不准”。选了“凭经验”或“说不准”，第 10、12 页会把对应的事标出来。
- 第 5 页：您现在用哪几个 OTA（四个空格）。填的名称会自动带到第 12 页“哪些 OTA”。
- 第 10 页：把月费摊到每个卖出的房晚（只问一个数：这家酒店每月卖出的房晚）。对照表是试点时填的。
- 第 12 页：今天只定三项（哪家酒店、哪些 OTA、验证哪件事）。点一下左边的事项卡片，就填进“验证哪件事”。
- 填写时按 Enter 或 Esc 结束输入；翻页笔在填写时也能直接翻页。
- 要把现场填的内容留给客户：控制条点“存为 PDF”，会后和 HTML 一起发。

**会后发给客户**：发对应语言的 HTML。在手机上自动变成竖向阅读，封面下有“先看结论”和快速跳转，顶栏可以换语言。

## 投屏版和阅读版不一样多

同一个文件，两种读法，字数不同：

- **投屏版只留要点**。每页一件事，主线 13 页平均每页约 280 字（中文，含标题、标签、截图标注和页脚），最多的一页不超过 400 字；讲的人补充其余内容。
- **阅读版（手机上、会后发给客户）保留补充说明**。例如每个问题下的一句解释、调价范围超出时怎么处理、ChatGPT 预订何时列入试点。这些句子在源文件里带 `only-read` 标记，投屏时不显示。
- 要让某句话只在阅读版出现，就在它的标签上加 `class="only-read"`；只在投屏时出现用 `only-present`。
- `selftest.js` 会检查投屏主线每页字数（单页 ≤ 400、平均 ≤ 300），往投屏版加字时超了会报出来。

## 已确认的口径

除事实表原文外，以下 18 项经确认后写入：

1. 听众：老板为主，经理在场。
2. 语言：中文为主，关键经营术语附英文；并支持切换 English、Bahasa Melayu。
3. 不点名任何“目前可接”的 OTA，只写“您已在用的 OTA，逐个核对”。
4. 可以写产品界面支持中文、English、Bahasa Melayu。
5. 不放开场视频。
6. “AI 浏览器”渠道栏实拍图不放（图里能看清具体平台名，和第 3 条冲突）；“AI 销售 · 开店指引”菜单图也没有放（审稿认为客户容易把它读成签约流程）。
7. 结尾只写 hi@intent-computing.com 和 hogentx.com。
8. 投屏和手机阅读两用。
9. 三个方案逐级包含。
10. 月费按每家酒店、每月。
11. 试点费用写“由双方另定”，不写免费。
12. “出了问题谁来处理”写成试点开始前的约定事项。
13. AI 浏览器（多 OTA 工作台）从专人陪跑方案（RM 2,499）起包含，工具授权不含。
14. 早安简报和四位数字员工三个方案都含。
15. 讲述顺序：主线 13 页；预订进度提醒的两个设置界面、早安简报与数字员工、点评与质检、AI 获客、名词对照放附页。
16. 方案和模块的英文、马来文名称按本稿的译法使用（见“英文、马来文”一节）。
17. “住小叮”在英文、马来文里保留中文原名。
18. 新加坡场次暂不处理；本稿只按马来西亚写。

## 英文、马来文

- 译文在 `i18n/strings.json`，每条含 `zh`、`en`、`ms`。中文是唯一的内容来源：改了中文，对应的译文要一起改，否则 `build.py` 会报缺翻译。
- 方案名的译法已确认按本稿使用：工具授权 = Tool Licence / Lesen Alat；专人陪跑 = Specialist Coaching / Bimbingan Pakar；OTA 全托管 = Full OTA Management / Pengurusan Penuh OTA。产品模块同理（智能收益 = Smart Revenue / Hasil Pintar，AI 浏览器 = AI Browser / Pelayar AI，AI 获客 = AI Guest Acquisition / Pemerolehan Tetamu AI，早安简报 = Morning Brief / Taklimat Pagi）。
- “住小叮”在英文、马来文里保留中文原名（已确认）。
- **马来文建议请母语同事通读一遍再对外使用**；英文也建议过一遍。脚本只核对了数字、否定与限定、标记是否齐全，不能代替母语校对。
- 英文、马来文句子比中文长，投屏时这两种语言的正文字号比中文小一号（最小不低于 18px，中文不低于 20px）。

## 没有放进客户版的内容

- 旧门店数（29、30、54）、内部测试与经营数字、市场数据、同行对比。
- 旧定价（RM 199、免费、测试期免费、抽成）、路线图日期、硬件试点、投资人叙事。
- 旧稿里未脱敏的截图、ChatGPT 卡片设计稿、门头照、吉祥物、开场视频、两张界面局部图。
- 任何增收、回本、省时的数字或保证（月费换算只保留“摊到每个卖出的房晚”，去掉了会被读成回本点的一列）。

## 客户很可能会问、但现有口径里没有答案的问题

页面上没有编答案，建议会前准备口头说法：

1. 客户正在用的 OTA 里，现在哪些能接？各自只能看，还是也能改价、回复点评？
2. 要不要接酒店管理系统（PMS）？要不要装软件？从授权到能用要多久？“授权登录”具体怎么做，能不能随时收回？
3. 数据存在哪里、谁能看、会不会接触住客资料？试点结束后怎么处理？
4. 合约期多长、含不含税、有没有开通费、怎么付款、中途能不能停？
5. 试点收不收费、多长时间、怎么算通过？（页面写的是“由双方另定”）
6. 出了问题找谁、多久回复？（页面写的是“试点开始前约定”）
7. ChatGPT 预订的“符合条件”指什么？客人下单、付款走哪条路？
8. 马来西亚现在有没有客户、有没有本地团队？住小叮的酒店在哪里？
9. OTA 全托管具体做哪些动作？和自己请人相比怎么样？
10. “净实收”扣哪些项？对照期取哪一段？现有经营报表能不能看到渠道佣金或净实收？
11. 用词是否符合客户习惯（房晚 / 间夜、质检、划线价等），需要按客户实际工作确认。

## 修改与重新生成

改中文只动 `src/deck.html`，改译文只动 `i18n/strings.json`，然后在本目录运行：

```bash
python3 tools/build.py
```

```bash
python3 tools/check.py
```

```bash
node tools/selftest.js
```

```bash
node tools/export-pdf.js
```

- `build.py`：把源文件合成三份单文件 HTML，并确认没有任何外部引用、没有缺翻译。
- `i18n.py`：`python3 tools/i18n.py missing` 列出还没翻译的文字；`list` 列出全部对照。
- `check.py`：口径自检。中文：扫描旧数字、旧定价、点名渠道、错误缩写（只能写 A2A、MCP）、自动改价和保证增收一类的说法；核对三档月费、31 / 56 的写法、每张截图的来源与验证范围。英文、马来文：数字与中文一致，否定和限定没有丢，没有多出的金额。
- `selftest.js`：功能自测 79 项（翻页、目录、三语切换、放大截图、现场填写、每页字数上限、三种语言逐页版面、手机阅读、关闭脚本、打印排版），需要 Playwright。
- `export-pdf.js`：导出三种语言的 PDF，需要 Playwright 和本机中文字体。

## 已知限制

- 只在 Chromium 里做了自动测试；Safari、Firefox 和真机（iPhone、安卓）没有实测。会前请用现场要用的电脑和浏览器过一遍。
- 现场填写的内容不保存。要留底请用“存为 PDF”或截图。

## 字体

中文使用系统黑体（苹方、微软雅黑、思源黑体），只用常规和加粗两个字重，所以在 Mac、Windows、手机上排版一致。西文和数字内嵌了 Inter 的子集（SIL Open Font License 1.1），英文、马来文正文也用它。
