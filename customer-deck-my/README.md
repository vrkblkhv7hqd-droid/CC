# HogentX · 给马来西亚酒店客户的汇报

面向马来西亚酒店老板（经理在场）的中文汇报，共 18 页。目的只有两个：让客户看懂**现在能用什么**、**值不值得试**。

事实口径以 2026-11-22 的《马来西亚酒店客户会谈资料》和随后逐项确认的 12 个决定为准；旧投资人汇报、旧开场视频里的数字和说法都没有沿用。

## 文件

| 操作 | 按键 |

鼠标动一下，底部会出现翻页条，几秒后自动隐藏。

**现场可以点、可以填的地方**（内容不保存，刷新即清空，换一位客户不会串）：

- 第 2 页：三个问题各有“有数据 / 凭经验 / 答不上”。选了“答不上”，第 15、16 页会把对应的事标出来。
- 第 5 页：渠道核对表，填客户正在用的 OTA。
- 第 15 页：试点约定单。
- 第 16 页：对照表，以及“把月费换算成您自己的数”（填每月卖出的房晚和每个房晚的净实收）。

**会后发给客户**：把同一个 HTML 发过去即可。在手机上自动变成竖向阅读，不依赖脚本。

## 已确认的口径

除事实表原文外，以下 12 项经确认后写入：

1. 听众：老板为主，经理在场。
2. 语言：中文，关键经营术语附英文。
3. 不点名任何“目前可接”的 OTA，只写“您已在用的 OTA，逐个核对”。
4. 可以写产品界面支持中文、English、Bahasa Melayu。
5. 不放开场视频。
6. 两张 PDF 之外的小图是“AI 浏览器”渠道栏实拍和“AI 销售 · 开店指引”菜单；已按“界面实拍局部”放入并加了限定说明。
7. 结尾只写 hi@intent-computing.com 和 hogentx.com。
8. 投屏和手机阅读两用。
9. 三个方案逐级包含。
10. 月费按每家酒店、每月。
11. 试点费用写“由双方另定”，不写免费。
12. “出了问题谁来处理”写成试点开始前的约定事项。

## 没有放进客户版的内容

- 旧门店数（29、30、54）、内部测试与经营数字、市场数据、同行对比。
- 旧定价（RM 199、免费、测试期免费、抽成）、路线图日期、硬件试点、投资人叙事。
- 旧稿里未脱敏的截图、ChatGPT 卡片设计稿、门头照、吉祥物、开场视频。
- 任何增收、回本、省时的数字或保证。

## 客户很可能会问、但现有口径里没有答案的问题

页面上没有编答案，建议会前准备口头说法：

1. 客户正在用的 OTA 里，现在哪些能接？各自只能看，还是也能改价、回复点评？
2. 要不要接酒店管理系统（PMS）？要不要装软件？从授权到能用要多久？
3. 数据存在哪里、谁能看、会不会接触住客资料？不想用了怎么收回授权？
4. 合约期多长、含不含税、怎么付款、中途能不能停？
5. 试点收不收费、多长时间、怎么算通过？（页面写的是“由双方另定”）
6. 出了问题找谁、多久回复？（页面写的是“试点开始前约定”）
7. ChatGPT 预订的“符合条件”指什么？客人下单、付款走哪条路？
8. 马来西亚现在有没有客户、有没有本地团队？
9. OTA 全托管具体做哪些动作？和自己请人相比怎么样？
10. “净实收”扣哪些项？对照期取哪一段？
11. 用词是否符合客户习惯（房晚 / 间夜、质检、划线价等），需要按客户实际工作确认。

## 修改与重新生成

改文字只动 `src/deck.html`，然后在本目录运行：

```bash
python3 tools/build.py
```

```bash
python3 tools/check.py
```

```bash
node tools/selftest.js
```

```bash
node tools/export-pdf.js
```

- `build.py`：把源文件合成单文件 HTML，并确认没有任何外部引用。
- `check.py`：口径自检。扫描旧数字、旧定价、点名渠道、错误缩写（只能写 A2A、MCP）、自动改价和保证增收一类的说法；核对三档月费、31 / 56 的写法、每张截图的来源与验证范围是否齐全。
- `selftest.js`：功能自测（翻页、目录、放大截图、现场填写、手机阅读、关闭脚本、打印排版），需要 Playwright。
- `export-pdf.js`：导出 PDF 备用稿，需要 Playwright 和本机中文字体。
